# Address flow without maps, and deferred capabilities

- `AddressDraft.point` coordinates are mandatory and never invented by the agent (ADR 0001). The typed-address assistant therefore parses and validates text only: `parse_and_validate_address` extracts street, landmark, pincode and contact phone (with `+91` normalisation for 10-digit Indian mobiles), reports missing fields, and detects a likely duplicate of an owned address by first street segment + pincode.
- The assistant never saves coordinates. After the customer confirms the parsed details, the chat shows an `info` card deep-linking to the app's address screen, where the device supplies the pin; the customer then returns to chat and the assistant re-reads `list_addresses` and continues the original order. Full typed-address saving with server-held candidates becomes possible when the maps service ships; the draft type `address` is reserved for it.
- Deferred by owner direction (17 November 2026): subscriptions (flag-respecting tools would be built only when the feature is enabled), recipe/meal-cart matching, coupons and substitutes (no customer-safe read contracts exist in those domains yet; DISCOVERY.md rows document where they belong).
- The nudge worker ships (opt-in, weekly cap, 7-day dedupe, UTC-week budget) but `agent_proactive_nudges_enabled` stays off in production until the Expo Go walkthrough passes.
