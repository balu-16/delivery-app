# Address flow without maps, and deferred capabilities

- **Updated 18 November 2026:** `AddressDraft.point` may be null for a saved written address. The assistant can save it only when the customer explicitly requests it and supplies the required fields in the current message. It never invents coordinates. `parse_and_validate_address` extracts supplied fields, normalizes Indian phone numbers, reports missing details and detects likely duplicates.
- A saved address may have no point. Delivery coverage is determined by the admin-managed PIN-to-store assignment. When the admin requires GPS, checkout requires the customer to confirm the actual location in the address screen. The app rechecks delivery and resumes a persisted shopping request using an idempotent message ID. Map search remains unavailable.
- The assistant can read available customer offers and guide the customer to choose an offer in the cart; eligibility and savings are verified there. Automatic substitute recommendations and replacements remain unimplemented: the customer may browse available products and explicitly choose an alternative. Subscriptions, wallet top-ups and recipe or meal carts stay out of scope.
- The nudge worker ships (opt-in, weekly cap, 7-day dedupe, UTC-week budget) but `agent_proactive_nudges_enabled` stays off in production until the Expo Go walkthrough passes.
