# Catalog

Owns categories, brands, products, variants, price windows, synonyms and durable CSV import jobs. Products and variants are soft deleted; SKU and barcode identities stay unique. Publication changes commit versioned history, audit and an outbox event together. Temporal prices use half-open non-overlapping windows and integer paise. Omitted/null `validFrom` activates at database time sampled after locks; a requested start that has passed (including during approval) activates at that time without rewriting historical periods. Large or material price changes require a distinct checker.

Customer reads resolve the store from the caller's owned selected/default address and require a published active product, an assortment row and a current price. Inventory's saleable view supplies availability; only low stock exposes a count. The SearchPort exposes index refresh, search and suggestions through the same PostgreSQL adapter. Search uses normalized exact, prefix, FTS and trigram matches with stock and popularity ordering. Suggestion cache entries use database revisions and expire before scheduled price or inventory boundaries.

Imports hash immutable bytes plus store and mode, validate the entire bounded UTF-8 CSV before writing and persist each batch with its checkpoint. BullMQ imports jobs carry hints to specific durable jobs; periodic database recovery recreates lost hints. Workers fence expired leases, retry transient failures with bounded backoff, and require approval for qualifying changes. Dry runs write only job metadata; authorized admins share real-run deduplication results. Import job state transitions have durable history. Error reports are persisted as immutable private objects with fenced recovery and authenticated CSV downloads.
